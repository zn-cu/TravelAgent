# 旅游策划书 · 汇总规则与模板

## 何时用

三个专家都返回结果之后，由 CEO 使用。不要在中间步骤用这份模板。

## 汇总的七条规则

1. **信息只能来自专家报告**。专家没给的数字写「待补充」，不要填空。
2. **金额零容忍**：预算表的每一项都要能在专家报告里找到出处。
3. **时间要自洽**：D1 上午的景点不能和出发时间冲突；返程车次必须在最后一天行程之后。
4. **每天都要落地**：三天的行程必须每天有具体安排，不能出现「自由活动」占位超过半天。
5. **冲突要暴露**：如果超预算或某天行程过满，明确写出来并给建议，不要粉饰。
6. **篇幅控制**：一页能看完最好。用户要的是能执行的方案，不是论文。
7. **地图链接可选但不要省事跳过**：只要景点报告里有经纬度，就必须尝试生成专属地图
   （调用 `maps_schema_personal_map`）。失败了才写「地图链接生成失败」，并说明原因。

## 生成「六、地图」这一节（两条链接，都要）

**① 主链接：每个景点一条 https 链接（手机点开即可唤起高德 App）**

调用本地工具 `build_amap_links`，把「名称|经纬度」用分号拼成一串传进去：

```
build_amap_links("大熊猫繁育研究基地|104.062,30.671;宽窄巷子|104.055,30.669;杜甫草堂|104.028,30.663")
```

- 经纬度**抄景点推荐官报告里的 `location` 字段**，顺序是「经度,纬度」。
- 返回值里 `links` 是数组，把每个 `name` + `url` 原样写进表格。
- 这是标准 https，微信、桌面浏览器、手机都能点，所以它是**主链接**。

**② 附加：高德「专属地图」唤端链接**

调用 `maps_schema_personal_map`，返回值通常形如 `amapuri://workInAmap/createWithToken?...`。
这是**高德 App 的私有协议，不是网页链接**，桌面浏览器和微信里点了没反应，属于正常现象。
所以：

- 单独放一行，并注明「需复制到手机浏览器地址栏打开」；
- **不要**把它当主链接，更**不要**改写或截断。

**③ 兜底**

任何一个调用失败，就写「XXX 生成失败：<原因>」，**绝对不许自己编一个链接**——点开 404 比没有更糟。

## 模板（照这个结构输出）

```markdown

- 目的地：成都 ｜ 天数：3 天 2 晚 ｜ 人数：2 人
- 出发地：北京 ｜ 出行日期：2026-XX-XX ～ XX-XX
- 总预算：¥4,320（含 10% 机动金）｜ 人均：¥2,160

## 二、每日行程
### D1（周X）｜主题：熊猫与老城
| 时间 | 安排 | 说明 |
|---|---|---|
| 09:00-12:00 | 成都大熊猫繁育研究基地 | 门票 ¥55/人，开园即进 |
| 14:00-16:00 | 宽窄巷子 | 免费，慢逛喝茶 |
| 晚上 | 春熙路 / 太古里 | 就近吃饭 |

### D2、D3 同上结构

## 三、交通方案
| 方式 | 班次 | 出发-到达 | 历时 | 门到门 | 票价 |
|---|---|---|---|---|---|
**推荐**：…（一句话理由）
**备选**：…（什么情况下改选）

## 四、预算明细
| 项目 | 单价 | 数量 | 小计 |
|---|---|---|---|
| 合计 | | | ¥X |
| 机动金 10% | | | ¥Y |
| **总计** | | | **¥Z** |

## 五、行前清单
- 预约类：故宫/博物馆这类需要提前预约的，列明预约时间
- 证件、药品、衣物（结合天气）
- 充电宝、雨具

## 六、地图
手机上点下面任一链接即可高德导航（会自动唤起 App）：

| 点位 | 打开 |
|---|---|
| 大熊猫繁育研究基地 | https://uri.amap.com/marker?position=104.062,30.671&name=大熊猫繁育研究基地&src=travel-agent&coordinate=gaode&callnative=1 |

`amapuri://workInAmap/createWithToken?...`

## 七、风险提示
- 天气：…
- 需要提前预约但可能约不到的：…
- 预算或时间上的取舍：…
```

## 交用户确认之前

调用 `confirm_itinerary(summary)`，把上面这份内容的**要点**（不是全文）传进去，
让用户在命令行里 approve / edit / reject。

- 用户选 `edit` → 按他改的参数重算受影响的部分，不要整条流程重跑。
- 用户选 `reject` → 问清是哪一块不行（景点？交通？预算？），只重做那一块。

## 用户通过之后：落盘

调用 `publish_proposal(markdown)`，传**策划书全文**（从 `# 标题` 一直到最后的「风险提示」）。

三条硬规则：

1. **不要**传「已为您保存」「祝您旅途愉快」这类寒暄 —— 工具会拒绝（少于 120 字），
   而且用户会下载到一段废话。
2. **不要**用 `write_file` 写策划书：那个走的是 Agent 的虚拟文件系统，用户下载不到。
3. **追问阶段不要调用**：还没拿到目的地/天数时，你的任务是把问题问清楚，不是落盘。
